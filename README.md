# نظام تقييم الأداء الوظيفي للمعلم

موقع كامل لإدارة ملفات الأداء الوظيفي للمعلمين: يضيف المدير المعلمين وعناصر التقييم، ويرفع كل معلم شواهده (صور / ملفات / روابط) تحت كل عنصر من صفحته الخاصة، مع شريط ودائرة تقدّم يتحدّثان تلقائياً مع كل شاهد جديد.

## هيكل الملفات

```
├── index.html          صفحة تسجيل الدخول
├── setup.html           إنشاء حساب المدير الأول (تُستخدم مرة واحدة فقط)
├── admin.html            لوحة تحكم المدير
├── teacher.html          صفحة المعلم
├── css/style.css         التصميم العام (الأزرق الملكي)
├── js/firebase-config.js إعدادات الاتصال بـ Firebase ← تحتاج تعديلك
├── js/common.js          أدوات مشتركة (الدخول، الحماية، تغيير البيانات)
├── js/admin.js           منطق لوحة المدير
├── js/teacher.js         منطق صفحة المعلم
├── assets/bg.jpg          خلفية الموقع
├── firestore.rules        قواعد أمان قاعدة البيانات (تُلصق في Firebase)
└── storage.rules          قواعد أمان تخزين الملفات (تُلصق في Firebase)
```

**كيف يعمل الموقع؟** الواجهة (HTML/CSS/JS) تُستضاف مجاناً على GitHub Pages، بينما قاعدة البيانات وتسجيل الدخول وتخزين الملفات تعمل عبر **Firebase** (خدمة مجانية من Google، لها باقة مجانية سخية تكفي مدرسة بالكامل). هذا هو الأسلوب الاحترافي المتّبع لأن GitHub Pages يستضيف ملفات ثابتة فقط ولا يستطيع تشغيل قاعدة بيانات أو حسابات مستخدمين بمفرده.

---

## الخطوة 1 — إنشاء مشروع Firebase (٥ دقائق)

1. اذهب إلى **https://console.firebase.google.com** وسجّل الدخول بحساب Google.
2. اضغط **Add project** → أدخل اسماً مثل `teacher-performance-eval` → أكمل الخطوات (يمكن تعطيل Google Analytics، غير ضروري).
3. من داخل المشروع، اضغط أيقونة **</>** (Web) لإضافة تطبيق ويب → أدخل اسماً مثل `school-web` → **Register app**.
4. ستظهر لك قيم `firebaseConfig` — انسخها، سنحتاجها في الخطوة 3.

### تفعيل تسجيل الدخول
`Build → Authentication → Get started → Sign-in method → Email/Password → فعّله (Enable) → Save`

### تفعيل قاعدة البيانات
`Build → Firestore Database → Create database → اختر وضع Production mode → اختر أقرب موقع خادم (مثل eur3 أو me-central) → Enable`

### تفعيل تخزين الملفات
`Build → Storage → Get started → استمر بالإعدادات الافتراضية → Done`

---

## الخطوة 2 — تفعيل قواعد الأمان

انسخ محتوى الملف `firestore.rules` من هذا المشروع، واذهب في Firebase Console إلى:
`Firestore Database → Rules` → الصق المحتوى بالكامل مكان القواعد الموجودة → **Publish**

ثم انسخ محتوى الملف `storage.rules`، واذهب إلى:
`Storage → Rules` → الصق المحتوى → **Publish**

> هذه القواعد تضمن أن كل معلم يرى ملفاته الخاصة فقط، وأن المدير وحده يستطيع إدارة المعلمين والعناصر، وأن لا أحد يستطيع إنشاء حساب "مدير" لنفسه من خارج الموقع.

---

## الخطوة 3 — ربط الموقع بمشروعك

افتح الملف `js/firebase-config.js` واستبدل القيم بالقيم التي نسختها في الخطوة 1:

```js
const firebaseConfig = {
  apiKey: "AIza...",
  authDomain: "your-project.firebaseapp.com",
  projectId: "your-project",
  storageBucket: "your-project.appspot.com",
  messagingSenderId: "...",
  appId: "..."
};
```

> **ملاحظة أمنية:** هذه القيم (خصوصاً `apiKey`) **ليست سرّية** ومن الطبيعي أن تكون ظاهرة في كود أي موقع ويب يستخدم Firebase — الحماية الحقيقية تأتي من "قواعد الأمان" (Rules) التي فعّلتها في الخطوة 2، وليس من إخفاء هذه القيم.

---

## الخطوة 4 — التجربة محلياً قبل النشر (اختياري لكن يُنصح به)

- في VS Code، ثبّت إضافة **Live Server** وافتح المجلد، ثم اضغط "Go Live".
- أو شغّل من الطرفية داخل مجلد الموقع: `python3 -m http.server 8080` ثم افتح `http://localhost:8080`.
- افتح `setup.html` أولاً لإنشاء حساب المدير (اسم مستخدم وكلمة مرور من اختيارك)، ثم سجّل الدخول من `index.html` وجرّب إضافة معلم وعنصر تقييم وشاهد.

## الخطوة 5 — رفع الموقع على GitHub

### أ) إنشاء المستودع
1. اذهب إلى **https://github.com/new**
2. اسم المستودع مثلاً: `teacher-performance-eval`
3. اجعله **Public** (مطلوب لتفعيل GitHub Pages مجاناً) → **Create repository**

### ب) رفع الملفات من جهازك
افتح الطرفية (Terminal) داخل مجلد الموقع ونفّذ الأوامر التالية بالترتيب:

```bash
git init
git add .
git commit -m "الإصدار الأول: نظام تقييم الأداء الوظيفي"
git branch -M main
git remote add origin https://github.com/USERNAME/teacher-performance-eval.git
git push -u origin main
```
استبدل `USERNAME` باسم المستخدم الخاص بك في GitHub.

### ج) تفعيل GitHub Pages
1. داخل صفحة المستودع في GitHub، اذهب إلى **Settings → Pages**
2. تحت **Build and deployment → Source** اختر **Deploy from a branch**
3. تحت **Branch** اختر `main` والمجلد `/ (root)` → **Save**
4. انتظر دقيقة إلى دقيقتين، سيظهر رابط الموقع أعلى الصفحة بالشكل:
   `https://USERNAME.github.io/teacher-performance-eval/`

### د) إضافة نطاق دخول الموقع إلى Firebase (خطوة مهمة جداً)
حتى يعمل تسجيل الدخول من الرابط المنشور، أضف نطاق GitHub Pages إلى القائمة المسموح بها:
`Firebase Console → Authentication → Settings → Authorized domains → Add domain`
أضف: `USERNAME.github.io`

## الخطوة 6 — الإعداد الأول بعد النشر

1. افتح `https://USERNAME.github.io/teacher-performance-eval/setup.html`
2. أنشئ حساب المدير (اسم، اسم مستخدم، كلمة مرور) — هذه الصفحة تعمل مرة واحدة فقط ثم تُغلق نفسها تلقائياً.
3. سجّل الدخول من الصفحة الرئيسية، وادخل **عناصر التقييم** واضغط **"استيراد العناصر الرسمية (11 عنصراً)"** لتحميل عناصر الأداء الوظيفي جاهزة كما في نموذج الوزارة (بالأوزان النسبية نفسها)، أو أضفها يدوياً وعدّلها كما تحب.
4. ابدأ بإضافة حسابات المعلمين من **إدارة المعلمين**.

## أسئلة شائعة

**هل الباقة المجانية من Firebase تكفي مدرسة كاملة؟**
نعم غالباً — الباقة المجانية (Spark) تشمل حتى 50 ألف عملية قراءة و20 ألف كتابة يومياً في Firestore، و5 جيجابايت تخزين ملفات، وهو أكثر من كافٍ لمدرسة بعشرات المعلمين.

**كيف يستعيد المعلم كلمة المرور إن نسيها؟**
يستطيع تسجيل الدخول ثم تغييرها بنفسه من "إعدادات الحساب". أما إذا نسيها قبل الدخول، فالطريقة الحالية أن يطلب من المدير حذف حسابه القديم وإضافته من جديد باسم مستخدم وكلمة مرور جديدين من **إدارة المعلمين**.

**كيف أغيّر الألوان أو الشعار؟**
كل الألوان معرّفة في أعلى ملف `css/style.css` تحت `:root` بأسماء واضحة (`--accent-teal`, `--bg-royal-1`...)، وتغييرها يغيّر الموقع بالكامل تلقائياً.

**هل أحتاج بطاقة ائتمان لتفعيل Firebase؟**
لا، باقة Spark المجانية لا تتطلب أي بيانات دفع.
